# 表格提取与保留

## 问题与目标

版本 current。原流程通过 get_text 保存逐行纯文本，丢失 PDF 的单元格、行列及合并关系。需要在原文件不变、已有索引不重建的前提下，统一修正阅读、导出及检索上下文。

## 内容模型

新增页面内容提取模块。页面由文本块与表格块按位置组成；表格保存行列数、表头行数及带 row／col／rowspan／colspan 的单元格。根据 PDF 实际边界推导跨度，不把空白单元格当作上一行的延续，不凭空补数值。优先使用表格线，在线框缺失时仅接受较高置信度的文本对齐表格。

原生 PDF 表格读取使用 PyMuPDF find_tables，识别与消费结果在进程内加锁，避免其表格提取状态在并发调用间串页。普通文字与表格区域分离，表格文本不再重复显示在正文里。多层表头及纵向合并保留为结构，页标题、单位、附注保留在原来的位置附近。

## 展示、导出和检索

- 阅读器按安全构建的 HTML table 展示，支持表头、合并单元格、横向滚动、复制 Markdown 与下载 CSV；全部单元格文本转义，不直接执行文档或模型返回的 HTML。
- 文档 Markdown 导出：简单表格输出 Markdown，包含合并单元格的表格输出规范 HTML；新增 HTML 导出保留合并结构，CSV 使用展开表头及合并值后的完整行。
- 问答与向量检索使用另一种表格表示：多层表头展开为完整列路径，合并值只按真实跨度填入每一行，使同一行的地区、类别、标准保持对应。
- 新上传的 PDF 在提取阶段保存表格语义，OCR 提示要求普通表格使用 Markdown、合并表格使用最小 HTML；服务端将其解析成相同结构，忽略脚本、样式及危险属性。已有 OCR Markdown 也可直接展示。

## 兼容与缓存

结构化页面缓存与原业务存储分离，文件仅当前用户可读，缓存键包含解析版本、PDF 引擎版本、原文件路径／大小／修改时间、页码及缓存文本摘要。旧文档访问时惰性提取，无需重新索引、覆盖 store.json 或调用模型。解析失败时保留可读文字并明确提示，扫描件缺乏表格结构时不伪造行列。

## 验证

使用用户差旅费 PDF 第 12–14 页核对：多层表头、河北等地区纵向合并、旺季期间及上浮价对应关系；验证正文不重复、表格数值不丢失、CSV 行列完整、合并结构导出和恶意 HTML 转义。复查普通正文页与已有 Markdown 的回退。默认不新增仓库测试文件，用临时验证脚本及浏览器核对页面，不修改原始 PDF，不连接付费模型。

已完成核对：第 12 页 25 行／10 列／3 层表头，第 13 页 26 行／10 列／3 层表头，第 14 页 4 行／5 列／2 层表头；第 4 页交通等级表也可识别，普通正文页未误判。单元格覆盖无缺口，HTML 结构往返后表头与数据一致，CSV 列数完整。真实接口验证了阅读、两种内容导出、单表下载和不存在表格的 404；读取过程未修改 store.json。桌面浏览器验证了合并展示与数值对应，390px 视口下表格局部横向滚动，页面没有横向溢出。

扫描件仍依赖视觉 OCR 的识别质量。本次用结构化 OCR 样本验证解析和安全转义，未调用用户的模型服务；旧 OCR 结果若只有散列文字，需要开启视觉识别重建索引才能恢复其表格结构。原生 PDF 的表格无需重建即可显示。

# 模型输入可见性

## 目标与边界

版本 current。用户需要核对实际提交给模型的检索内容。现有检索步骤与引用只描述流程，不能作为真实输入凭据。新增每次问答的模型输入快照，在调用 SDK 的位置采集，不通过后续再次检索来重建，也不使用摘要冒充正文。

## 内容与交互

每条新回答显示「查看模型输入」，流式生成时即可打开。弹窗沿用阅读室风格，分为「检索原文」与「完整调用」：前者原样显示本次回答使用的上下文、真实字符数、截断及文档页码；后者逐次展示树检索、向量查询／文档编码、回答调用的模型、用途、调用状态，以及完整 messages 或 input。支持复制与下载 JSON。正文与表格使用可滚动的纯文本展示，保持提交给模型时的原始字符与顺序。

树检索提交的是目录／章节摘要预览和问题；回答提交系统提示、最多十条历史消息、检索上下文及当前问题。向量检索展示实际提交的文本，缓存命中时明确说明没有再次发送文档内容。截断仍按现有业务限制执行，同时公开最终原文与截断前后字符数；没有进入最终上下文的尾部来源不再列作回答引用。

## 采集与存储

通过请求范围内的 ContextVar 观察器采集实际 SDK 调用参数，记录应用显式发起的重试和兼容重试；SDK 内部的网络重试不单独计数。记录模型与内容等白名单字段，排除 API Key、认证头和连接密钥。无观察器时不复制内容、不影响索引与 CLI。供应商与 SDK 内部的协议转换不属于本功能；界面准确标注为应用提交给 SDK 的调用输入。

完整快照存于本地 model-input-traces/，文件权限 600，目录 700；会话消息只记录快照 ID 和概要，避免重复加载所有历史正文。历史回看接口验证快照属于指定会话中的消息。会话删除时清理对应快照。旧消息未采集，不补造输入；界面明确说明旧记录不提供历史快照。失败与主动停止时也保留已经发起的调用，不标成成功。

## 验证

不新增仓库测试文件。使用临时隔离数据与模拟模型服务，对照模型端收到的 messages／input 与快照逐字一致；覆盖树检索、向量缓存、流式回答、截断、失败／停止、历史回看、无权限关联与旧消息回退。通过编译、脚本语法和浏览器检查验证，无需调用用户真实付费模型，不修改已有文档。

## 验收结果

- 本机模拟服务逐字对照通过：目录筛选 messages、回答 messages（含历史）、向量 input 与快照一致；覆盖混合检索、向量缓存、兼容重试、失败／停止及独立会话关联验证。
- 超过 100,000 字符时，界面与快照只展示实际提交部分；完全未提交的尾部来源不列作回答引用。
- 浏览器通过真实网页发送问题，验证实时事件、历史回看、完整 JSON 查看及下载；390px 视口无页面横向溢出，控制台无错误。
- 验证初次误用了模块固定路径下的项目模型注册表，实际执行一次问答的目录筛选与回答调用；已告知用户，随后显式替换为模拟注册表，增加只允许本机 socket 连接的验证限制。实际业务存储与原文文件未写入测试数据。

已通过 38 项现有索引／Markdown／树结构测试，以及并发观察器隔离、密钥字段排除、会话删除清理快照的轻量验证。停止后可刷新服务端持久化快照，避免只看到浏览器中断前收到的部分输入。用户 store.json 与改动前哈希一致。
